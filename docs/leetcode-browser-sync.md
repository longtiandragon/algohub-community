# 力扣浏览器同步

平台账号中先绑定并验证力扣账号，再进入 `/leetcode-sync` 安装脚本、生成连接码。在力扣登录同一账号后，通过右下角紧凑面板同步。无需复制 Cookie。

## 数据口径

- 总过题数继续来自服务端查询的力扣公开统计，不用最近 15 条记录的数量替代。
- 插件读取“进展分析”的题目分页，再分页读取每道题的全部提交，只上传 AC 明细。不上传代码、密码、Cookie 或失败提交。
- 同一提交编号幂等保存；重复 AC 保留为提交明细，但每题只产生一个通过关系。
- 热力图使用 `FIRST_AC`：按每题最早 AC 时间、北京时间自然日计一次。不能使用力扣主页的提交次数热力图替代。
- 公开动态沿用归属验证与隐私规则，按原 AC 时间归档，不按导入时间生成新动态。
- 浏览器记录标记为 `USER_REPORTED`，不冒充服务端独立核验的 `EXACT`，不将账号的服务端 `history_complete` 改成真。

## 完整性与授权

每页校验数量、重复编号、字段和时间。整轮结束再次读取题目列表、账号和做题进度，核对 AC 题目数与公开总数。缺页、超时、数量变化或账号切换均停止上传；后端分批暂存，整轮收齐才合并。

连接码仅用于一个已验证账号，60 分钟有效；自动同步需明确开启，授权 90 天有效且可撤销。自动同步仅在力扣页面打开时运行，默认间隔 6 小时。本轮最多读取 20,000 次提交，超限不声称完成。

## 源站依据与验证

2026-10-29 从力扣官方前端资源 `pages/progress-650efaa6cdd57594.js` 和 `_app-702470f65471ddc3.js` 确认：

- `/graphql/`，`userProgressQuestionList(filters: {skip,limit})`。
- `userProgressSubmissionList(offset,limit,questionSlug)`，返回 `totalNum` 与 `submissions {id,status,langVerboseName,timestamp}`；AC 枚举为 `AC`。

匿名调用提交查询返回 HTTP 200、数据为 null；没有登录时不能读取历史。自动化测试使用合成数据，不代表已在真实登录账号完成插件端到端同步。

## 2026-10-30 读取加速与上传续传

洛谷 v1.3.0、QOJ v1.1.0、力扣 v1.1.0 统一使用请求节流：正常请求开始间隔至少 750 ms；洛谷与力扣最多两个读取任务并发，QOJ 沿源站分页逐页读取。HTTP 429 后降为至少 3 秒，并遵守 `Retry-After`；网络异常和服务端错误最多重试两次。较长的限流等待会停止本轮，避免长期挂起。

三个脚本都按 500 条一批上传。例如 1,001 条 AC 记录上传 3 批。源站仍完整读取并复核；加速没有省略旧记录，也不改变热力图按每题首次 AC 计数的规则。

读取和复核完成后，脚本在 Tampermonkey 存储中暂存精简记录、连接码及已确认的批次，最多保留 20 分钟。上传失败时可在设置中点“续传上次上传”；刷新页面也可恢复，但仅续传同一连接码、同一账号的快照。连接码失效或改用新码需要重新同步。读取尚未完成时的中断不支持断点恢复；正常新一轮也不是只抓新记录的增量同步。

后端 V59 增加分页内容摘要，完全相同的重传返回原批次结果，内容改变则拒绝。最后一批即使响应丢失，也不会再次合并统计。完成后删除暂存明细，摘要沿用连接码的有效期，新连接会重置摘要。三个导入服务的暂存写入改用 JDBC batch。脚本与后端需要配套发布，本次仍仅修改本地。

回归入口：前端 `npm run test:browser-sync`，覆盖三个实际脚本的分页、1,001 条记录、重复 AC、首次时间、断网重试、刷新续传、切换账号、缓存过期、响应丢失和限流退避。后端从 `backend` 目录执行 `mvn -Dtest=BrowserImportRetryTest,LuoguBrowserImportTest,QojBrowserImportTest,LeetCodeBrowserImportTest test`。这些是本地模拟源站和数据库测试，不代表真实账号网络速度测量。
