# GitHub 协作与发布设置清单

本文件是维护清单。公开仓库为 longtiandragon/algohub-community；具体启用状态须以 Settings 实际结果为准。

- Issues：已在创建公开仓库时开启。
- 默认分支：要求 PR 合并，禁止强制推送及删除。单维护者可不要求他人审批，以免无法合并；多人维护时至少 1 位审批，并明确例外权限。
- 必需检查：工作流定义包含 `backend`、`frontend`、`secrets`、`dependencies`。先让工作流实际运行成功，再从设置里选择 GitHub 显示的真实检查名，不能设置不存在的名称。
- Fork PR：普通 CI 不用生产秘密，只读权限，无自动部署；审核首次贡献者运行权限。工作流修改也须审阅。
- Dependabot：仓库已有更新配置；安全提醒、依赖图、私密漏洞报告和分支规则能否在当前私有仓库启用，取决于账户方案和权限，须以 Settings 实际结果为准，不能因为有配置文件就声称启用。
- 生产：独立受保护 environment、独立凭据、明确批准人，仅受信任发布路径使用。禁止带生产秘密的任务执行不可信 PR 代码或消费未验证的外部构建产物。
- 发布：用户批准后创建版本标签及 Release Notes，列出迁移、兼容性、已知限制和回滚条件；数据库不兼容时不能仅回滚 jar。正式发布不由本任务自动执行。

每次发布前查看 [验收记录](open-source-readiness.md)，通过 CI 后发布，并保留迁移与回滚说明。
