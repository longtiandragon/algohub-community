# 累计榜修复与 QOJ 可行性验证记录

## 累计排行榜

从原工作区仅按 Git 补丁迁移以下四个文件的本次修改，未复制工作区、配置或其他未提交内容：

- `CampusRankingMapper.java`
- `CampusRankingService.java`
- `StatisticsMapper.java`
- `CampusRankingTest.java`

普通平台按已验证账号分别取已收录去重题数与最新累计快照的较大值，再汇总。洛谷保留跨账号明细去重，并与该平台最大的最新账号快照比较，不重复叠加额外评测。最新快照按 `captured_at DESC, id DESC` 选取。排行的认证及隐私过滤继续生效。

累计数字不作为提交明细或时间证据。时间榜、热力图和公开动态继续读取原有真实记录。

新增验收用例使用合成数据验证：力扣 389 + 洛谷 250 + 牛客 33 = **672**，已收录明细仍为 **295**；相同时间的较晚快照可以小于之前的值；洛谷重复账号及额外评测不重复相加；无时间明细和快照不生成时间榜、热力图、动态或提交。

迁移后在新工作区独立重跑 `CampusRankingTest` 与 `StatsVisibilityTest`，原补丁的 19 项全部通过。随后新增上述验收用例。完整回归还发现 `MultiAccountStatisticsTest` 的一处旧断言要求普通平台的累计榜跨账号去重，与新口径冲突；在新工作区补充调整该断言，同时明确验证累计数 3、去重明细 2，并直接比较档案 `totalPassed`。没有从原工作区迁移其他改动。

认证边界检查还发现，本人档案的洛谷去重明细原来包含未认证账号，但 `totalPassed` 的其他平台和快照仅包含认证账号。因此在新工作区补充修复 `StatisticsService`：用于累计总数的洛谷明细也只取已认证账号。本人可查看的未认证明细继续单独保留。新增测试验证混合认证状态下档案累计数、学校榜和全站榜相等，且他人档案不暴露未认证明细。

最终本机 `mvn -B -Prelease verify` 成功：678 项中 **676 项通过，2 项默认关闭的外部实时测试跳过，0 失败、0 错误**。其中 `CampusRankingTest` 16 项、`StatsVisibilityTest` 5 项全部通过。数据库使用本次专用 PostgreSQL 容器的 `_test` 库，Redis 使用另一专用容器的非零逻辑库，没有对生产数据运行测试。前端类型检查、生产构建、浏览器同步及其余 CI 页面脚本全部通过。

## QOJ：未达到上线及旧绑定迁移条件

2026-10-30 使用实际生产服务器网络访问 QOJ 登录页，HTTP 返回 **403**，响应头为 `cf-mitigated: challenge`，页面标题为 `Just a moment...`。普通请求和带浏览器 User-Agent 的请求均未取得可用登录页。本机曾取得登录页，但后续准备登录的请求也返回 403。

未绕过访问限制，未提交登录凭据，未导入客户端登录态。

下列能力仍未实测确认，不能据此宣称支持：

- 邮箱能否登录及对应的站内用户名；
- 平台账号读取其他用户主页、Motto、通过题数和提交分页；
- 可见历史与累计通过数的统计范围及权限差异；
- 满分记录与 AC 的对应关系、比赛及受限记录的可见性；
- 服务器会话续期、Motto 验证和服务端历史回填。

现有解析器直接把 `data-score=100` 且 `data-full=100` 当作 AC；该规则没有取得本次真实页面证据，不可据此启用新服务端采集。

本次没有实现或发布 QOJ 新绑定流程，没有解除旧绑定、撤销旧插件或发出升级通知。生产库只读统计为 **3 个绑定、3 位用户，其中已认证账号 0 个**。QOJ 迁移数 **0**，通知数 **0**。解除生产服务器访问限制并完成真实登录与跨账号分页验证后，才能继续新流程实现、隔离测试及发布前备份与迁移。
