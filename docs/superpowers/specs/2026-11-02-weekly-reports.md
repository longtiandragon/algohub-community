# 周报提交、统计与提醒需求

用户已确认本清单，并授权实现、验证后发布 Issue 和 PR。

## 业务规则

- F01–F05：活跃、已审核学生可创建本人本校自然周周报，学习总结必填，问题和下周计划可选；草稿可保存删除；提交后不可覆盖，退回后可修改并重新提交；本人可读历史内容和评价。不得创建未来周次、加入学校前周次。自动刷题报告不代表提交。
- F06–F08：学校管理员或具备学校与成员权限的平台管理员管理学校内周报；有效年级负责人只管理明确授权学校及入学年级。只可读已提交版本及处理历史，不能读草稿和未重新提交修改。评价、退回留记录，不能自评，过期版本操作拒绝。
- F09–F14：统计默认关闭。开启需有效配置；关闭二次确认并立即停止未发提醒和后续统计。北京时间自然周，星期一至星期日、分钟精度；提前小时为非负整数且提醒不得早于周一，0 不提醒。首次配置可用于本周未来时点，后续修改下周生效，本周和历史不追溯。重新开启不补关闭期间错过的任务。显示当前/待生效配置、下次执行时间及邮件可用情况。
- F15–F19：提前时点只提醒当时未提交的应交学生；邮件仅本人已验证登录邮箱，尊重个人邮件开关，站内消息保留。每学生/学校/周仅一条业务提醒；发送前复查资格、开关、提交状态和截止时间；有限重试，成功不重发；关闭和过期提醒不积压补发。区分无邮箱、个人关闭、邮件服务不可用、失败、取消和过期；汇总不展示完整邮箱、正文或内部错误。
- F20–F25：应交范围为统计时活跃已审核普通学生，排除平台和学校管理员，包含年级负责人。学号、班级缺失不免报；年级缺失仅学校负责人管理，刷题月目标0或年级停止开放不免报。截止时已提交、已评价算完成，草稿、未创建和退回算未交。生成应交/已交/未交人数及未交快照；无人未交也有完成记录；重复执行不能重复。快照保存截止前姓名、学号、班级、年级、状态和最后编辑时间、提醒结果及截止/生成时间。补交只附加时间和当前状态，不改原结论；失败自动重试必须还原截止状态，不能用现状伪装。
- F26–F28：名单按周、年级、班级、姓名/用户名/学号、补交、提醒状态筛选并分页。详情区分截止状态和当前状态。关闭后学校管理员可读历史，年级负责人不可读统计名单；个人报送和管理评价仍可用。
- F29–F31：所有入口服务端重新验证权限；普通学生不得读配置、名单或自己入名单信息。年级负责人本人仍应提交，但不能自评或读取本人名单/提醒明细，其管理汇总排除本人。撤销、离校、停用、角色/成员变化沿用现有授权失效规则；历史记录保留原学校/年级，移校不转移历史。配置、评价、退回等留审计，站内消息仅本人可见。

## 本期边界

不增加学校时区、真实姓名采集、负责人邮箱读取、附件、打分量表、导出、手工重算/补发、按学校删除历史、补交自动移除、免报名单。提交评价与统计开关分开。历史草稿不对管理者开放。默认周日22:00、提前6小时、邮件开启的配置仅作为表单默认值，学校功能仍默认关闭。

## 验证标准

用虚构学校和账号验证两校/两年级隔离、本人数据隔离、角色撤销、草稿/退回/评价、乐观版本冲突、截止精确状态、迟到补交、名单筛选和分页、历史归属、配置跨周生效、关闭后取消待发、邮件退出/无邮箱/失败重试/重复任务、跨周待统计恢复。完整后端verify、现有前端回归及新增周报回归、类型检查、构建、真实浏览器桌面/390px流程、Gitleaks后发布。迁移仅新增，不改已发布迁移；不使用真实邮箱和用户数据做测试。
