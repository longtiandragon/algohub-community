# [Feature] 支持学校管理员委派年级负责人（队长），管理指定年级学生

已提交：[Issue #12](https://github.com/longtiandragon/algohub-community/issues/12)。

## 使用场景

学校集训队常由学生队长或年级负责人协助老师管理同届同学，例如审核入校申请、核对班级和学号、查看学习情况。希望学校管理员能够从本校已审核学生中任命负责人，委派指定入学年级的日常成员管理工作。

这里的年级沿用系统已有的入学年级，例如“2026 级”。

## 当前问题

目前学校管理员具有本校范围的管理权限，普通学生没有成员管理入口。把队长直接设为学校管理员会使其管理范围扩大到全校，无法表达“只负责本校某一年级”。

现有实现中，`school_administrator` 记录学校授权，`school_member.enrollment_year` 记录成员年级，学校管理入口位于 `/api/school-admin`，可以在此基础上增加年级委派机制。

## 建议方案

新增“年级负责人（队长）”委派身份，保持其普通学生账号角色不变。

- 学校管理员可以任命、撤销自己负责学校的年级负责人。
- 候选人必须是本校已审核、状态正常的学生；一届允许多名负责人。
- 每项授权明确记录学校、管理年级、负责人及授权人，分别控制和撤销。
- 任命界面默认使用候选人本人的入学年级，学校管理员明确确认实际管理年级。
- 学校管理页提供负责人设置，被任命学生获得“本届管理”入口。

### 负责人可以做什么

| 能力 | 范围 |
| --- | --- |
| 查看、搜索成员名单及审核状态 | 本校被授权年级 |
| 审核普通学生入校申请 | 本校被授权年级 |
| 修改班级、学号 | 本校被授权年级 |
| 查看学生学习档案 | 本校被授权年级的已审核学生 |

### 权限边界

- 不能管理其他学校或未授权年级，不能任免其他负责人。
- 不能修改成员的学校、入学年级，不能审核本人或管理学校管理员、平台管理员。
- 不能通过拒绝另一名有效负责人的成员身份来间接撤销对方授权。
- 查看学习档案不额外开放邮箱、平台凭据、私人收藏或社交权限；原有隐私规则继续适用。
- 原有普通用户可以浏览的公开档案，仍可正常浏览。
- 权限由服务端逐请求检查，列表、搜索、计数、单条修改和档案数据接口使用一致范围。
- 撤销授权、负责人离校、本人年级或学校身份变化后，旧授权失效；把资料改回原值不会自动恢复。
- 任免、审核、资料修改和非公开档案访问留审计记录。

第一版聚焦上述成员管理，不包含目标分配、提醒发送、训练活动或公告管理。

## 替代方案与兼容性影响

可以直接在学校成员记录中增加队长标记，但会将负责人身份与本人年级绑定在一起，难以独立表达管理范围及任免历史。建议使用独立授权记录，沿用学校管理员授权机制的思路。

该方案需要新增数据库迁移、负责人授权和管理接口、本人身份返回字段以及前端入口。已有学生不自动获得新权限，学校管理员原有权限保持兼容，不修改已发布的 Flyway 迁移。

## 建议验收条件

- [ ] 学校管理员能任免本校负责人，重复任命不产生重复授权。
- [ ] 普通学生、未审核成员和其他学校管理员不能越权任命。
- [ ] 负责人只能查看、审核和修改授权年级内允许管理的学生。
- [ ] 伪造学校、年级或成员 ID 不能越权，名单计数与搜索也不泄露其他范围。
- [ ] 班级和学号可修改，学校、年级及其他字段保持不变。
- [ ] 学习档案和各统计入口按同一范围限制，保留邮箱和平台账号隐私规则。
- [ ] 撤销或学校身份变化后，原登录令牌不能继续管理；资料改回不会恢复授权。
- [ ] 任免及成员操作有审计，原学校管理员与平台管理员权限测试仍通过。
- [ ] 桌面端、移动端可完成任免和成员管理，切换范围不会显示上一次请求的数据。

## 贡献意向

愿意按维护者确认的权限范围实现，并补充跨学校、跨年级、撤销生效和隐私相关测试。

该范围已完成本地实现，包含权限、生命周期和并发回归，以及前端页面验证；实际结果见 docs/cohort-leaders.md。当前尚未向 GitHub 发布或部署，本地测试结果不代表生产验收。
