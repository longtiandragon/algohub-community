# 邮箱验证码与 GitHub 登录

## 邮箱登录

邮箱登录使用验证码，不要求密码。首次成功验证会创建学生账号和随机平台用户名，昵称可在设置中修改；不会自动加入任何学校，也不会依据邮箱域名授予权限。

已有用户名账号应先登录，在「设置与安全 → 登录邮箱」中验证邮箱。不要直接用尚未绑定的邮箱走首次登录，否则会创建独立账号。旧资料邮箱不会自动视为已验证，也不据此自动合并账号。

设置页支持查询、绑定、更换和移除登录邮箱。更换时原邮箱一直保留到新邮箱验证成功；邮箱为唯一登录方式时拒绝移除，仍可直接更换邮箱。GitHub 解绑会检查是否还有密码或已验证邮箱可登录。

验证码 10 分钟有效，验证失败最多 5 次，成功后消费；登录验证码与绑定验证码分开存储和校验。登录邮件按 IP 和邮箱做 60 秒发送冷却。只存验证码摘要，接口和日志不返回验证码。邮件投递测试使用模拟发件器，不代表真实收件成功。

## 发件配置

默认不启用邮件，页面明确显示尚未配置，不使用假验证码或日志验证码作为正式登录入口。

启用 `mail` Spring profile，并设置环境变量：`MAIL_HOST`、`MAIL_PORT`（默认 587）、`MAIL_USERNAME`、`MAIL_PASSWORD`、`MAIL_FROM`。配置文件为 `backend/src/main/resources/application-mail.yml`，默认使用 SMTP AUTH 与 STARTTLS，连接、读写超时均为 10 秒。若发件服务只支持隐式 TLS 的 465 端口，需按服务方配置改用 SSL；不能只修改端口。

不要把 SMTP 密码写进仓库或聊天记录。配置好后再做真实邮箱收件、过期、重发、注册、登出后验证码登录的完整验收。学校邮箱域名暂不设限制，学校成员体系独立处理。

## GitHub

已有 GitHub 登录、授权绑定和解绑流程，复用平台会话；需要配置真实 OAuth App 的 client id、client secret 与正确回调地址。当前没有实测第三方授权，不能把源码已有入口等同于真实 GitHub 登录已验收。

2026-09-23 起 GitHub 可以直接注册：没绑定过的 GitHub 账号第一次登录即自动开户，与邮箱验证码首次登录一致（不设密码、
不自动加入学校），之后按注册流程选择学校。邮箱的处理参照 GitLab 等平台的通行做法：

- 新账号的登录邮箱取 GitHub 已验证的主邮箱（需要 `user:email` 只读权限；跳过 noreply 地址），取不到时和注册一样到站内验证；
- GitHub 身份按 GitHub 数字 ID 单独记录在 `user_oauth_binding`，与登录邮箱分开：开户时两者相同，之后各改各的互不影响；
- 这个邮箱已是本站其他账号的登录邮箱时不自动合并、也不再开新账号，提示先用原账号登录后在「账号安全」绑定
  （GitLab 默认同样如此，自动按邮箱合并需要管理员另外开启）。

GitHub 的网页与 API 地址可配置（`algohub.oauth.github.web-base-url` / `api-base-url`，默认 github.com / api.github.com），
用于 GitHub Enterprise 或本机模拟联调。2026-09-23 用本机模拟 GitHub（假 client，真实密钥不外发）在浏览器里走通了整条流程：
新生首次登录 → 选学校 → 首页、再次登录不重复开户、无已验证邮箱转去验证邮箱、邮箱被占用给出提示、取消授权、已有账号绑定后
用 GitHub 登录。真实 GitHub 的授权页需要本人登录 GitHub 完成。

配置方法见 README「GitHub 绑定」：OAuth App 回调地址为 `http://127.0.0.1:5174/oauth/github/callback`，client id / secret
写在 `backend/local-secret/github.properties`（不进仓库，启动脚本会读取）。回调地址默认值原先写的是 5173（本机另一个项目的端口），
2026-09-23 已改为 5174。后端换取令牌时要直接访问 `github.com` 与 `api.github.com`，网络不通时会提示「无法连接 GitHub」。

本轮改动集中于邮箱身份与登录方式保护，不新增训练题单、收藏、积分等扩展功能。
