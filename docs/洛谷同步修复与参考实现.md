# 洛谷同步修复与参考实现

2026-09-13 实际检查的参考源码：

- OJ Insight：https://github.com/Whalica/OJ_Insight/blob/main/src-tauri/src/sync/luogu.rs
  - 练习页 `/user/{uid}/practice`，请求头 `x-lentille-request: content-only`。
  - 数据读取 `data.passed`；主页 `dailyCounts` 属于活动汇总，不能当作逐条提交。
  - 其实现不返回洛谷逐条 submissions，并非完整提交历史采集器。
- oj_helper：https://github.com/2754LM/oj_helper/blob/main/lib/services/solved_num_services.dart
  - 用户搜索后读取个人主页，通过 `passedProblemCount` 提取总量。
  - 不能据此获取每道题的提交时间。

本项目以独立 Java 实现接入上述数据路线，没有复制桌面应用代码。

## 原问题

旧适配器请求 `?_contentOnly=1`，读取 `currentData.passedProblems`；还把任何 HTML 判为凭据失效。文件解析与 CSV 导出没有接到数据库，页面统计因此不包含洛谷。之前关于已完成洛谷统计的表述不准确。

## 本次改动

- 新请求路径和请求头，兼容 content-only JSON、lentille-context HTML 以及旧编码 JSON。
- 验证 UID、题目字段和报告总数；防护页与凭据过期分开，不把失败保存成零。
- 将题号、标题、链接、原始难度和通过关系存入 problem/user_solved_problem，按账号和题号幂等。
- 不生成虚构 submission 或 AC 时间，不将回填题目集中写入当天热力图。
- 档案总量、平台分布、难度分布直接读取入库数据。
- `/api/history/solved?platform=LUOGU` 仅返回当前登录用户的已通过题单；网页导出支持直接读取，不必上传 HTML。

## 每日活动接入（2026-09-13）

参考 OJ Insight 的活动数据读取方式，读取主页 dailyCounts 每日数组的第一项，第二项不作含义推断。独立保存为 PLATFORM_ACTIVITY / PLATFORM_AGGREGATE，沿用源站日期，不混入 FIRST_AC、逐条提交、累计去重题数。缺失日期不推断为已确认零，保留以前已抓取日期。

主页活动读取失败时保留旧活动，已通过题单仍可正常更新；最新快照附加说明记录活动是否读取成功。重复同步按账号、日期、指标覆盖，不叠加。校验 UID、日期、非负整数及数值范围后才写入。
